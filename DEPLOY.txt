PWA / CACHE
- The service worker is registered only in production and only after the cloud profile is confirmed.
- It intercepts same-origin shell/assets only; Firebase/Gemini/Google requests are never intercepted.
- A new worker no longer calls skipWaiting(), so it cannot delete the previous shell cache while an
  already-open old client may still need old lazy chunks. The new worker activates naturally after
  old clients close.
- Splash video is runtime-cached instead of install-time precached.

V5.3.2 RELEASE HARDENING
========================

Firestore Security Rules
------------------------
The repository now includes firebase.json + firestore.rules. Deploy the checked-in rules
with Firebase CLI from the project root after selecting the correct Firebase project:

  firebase deploy --only firestore:rules

The rules are default-deny and allow authenticated users to access only
/users/{their-own-uid}/data/**. Review them before deployment if you add any new Firestore
collections outside this canonical path.

App Check / reCAPTCHA Enterprise
--------------------------------
The client now prefers ReCaptchaEnterpriseProvider when the production build receives:

  VITE_RECAPTCHA_ENTERPRISE_SITE_KEY=<your score-based Enterprise Web key>

Before setting it, create a score-based reCAPTCHA Enterprise Web key for the production
domains and register that same key for this Web app in Firebase Console > App Check.
Until that provisioning is complete the existing reCAPTCHA v3 provider remains as a safe
compatibility fallback, so this release does not lock existing users out.

Dependency lock / production build
----------------------------------
This source archive intentionally does NOT contain a fabricated package-lock.json. The QA
environment could not reach registry.npmjs.org, so a trustworthy transitive lock graph could
not be generated or a real Vite build executed here. On a machine with npm registry access,
run once:

  npm install
  npm test
  npm run test:syntax
  npm run build

Commit the generated package-lock.json. After that, releases should use:

  npm ci
  npm run verify:release

Upload only dist/ to hosting.

# MIND.EXE — handoff

Current development release: **v5.3.2 — FINAL QA candidate**.
Base: v5.2.1 Approach 1 re-audit + v5.2.0 Approach 2 Decision hardening.

## What Approach 3 changes

### Production dependency graph

Runtime import maps/CDNs are removed from `index.html`:
- no esm.sh React/Recharts/Lucide;
- no gstatic Firebase module URLs;
- no Tailwind runtime CDN;
- no blocking Google Fonts request.

`package.json` now owns React 18.3.1, Firebase 12.17.1, Lucide 0.383.0 and Recharts 2.12.7. Vite 7.1.5 is the production bundler and Tailwind 4.1.10 is compiled before build.

`styles.css` is generated by `scripts/generate-css.mjs`; the production page loads that static stylesheet.

### Code splitting

Heavy feature UI is now lazy-loaded:
- Dashboard/Home/Patterns/Challenge (and Recharts)
- Strategy Lab
- Settings
- Coach
- Calibration
- Decision Lab

Pure Strategy math was moved to `core/strategy-math.js`, so app orchestration can use Strategy calculations without eagerly loading the Strategy UI. Dashboard storage configuration moved to lightweight `features/dashboard/dashboard-data.js` so the chart/UI module can remain lazy.

### Fast profile bootstrap without stale writes

A local profile snapshot can render before Firestore finishes only if it carries the new v5.3.2 `full-v1` confirmation marker. Old v5.2.x shadows are deliberately not trusted for fast bootstrap because older `ProfileStore.save()` returned a chunk-stripped public profile to the local shadow path.

Rules:
1. cached confirmed snapshot may render immediately;
2. writes remain disabled (`canPersistRef=false`);
3. UI remains read-only while Firestore verifies the current revision;
4. only successful cloud load/CAS save marks the local snapshot confirmed;
5. any optimistic pre-save local shadow invalidates the confirmation marker until cloud commit succeeds.

This prevents a stale/partial local shadow from becoming an authoritative writable state.

### Profile Store performance

`core/profile-store.js` keeps the same Profile Store version/key layout/manifest CAS semantics, but immutable revision documents (core + journal chunks + ledger chunks) now write concurrently. Manifest activation begins only after every immutable write succeeds. Any partial failure deletes all planned revision keys and never touches the manifest.

A bug found while implementing bootstrap was also fixed: `save()` now returns the full normalized public profile, not the chunk-stripped core copy. This matters for the local shadow and `rawProfileRef`; cloud document layout is unchanged.

Legacy backup preparation is scheduled in idle time after cloud load so it normally does not block the user's first save. Existing synchronous fallback remains if preparation did not complete.

### Startup network priority

- Strategy load waits for `cloudProfileReady` and begins through idle scheduling.
- Decision↔Journal reconciliation waits for cloud profile readiness.
- Existing Home background AI idle scheduling remains.
- Progressive Journal screenshots remain background-only.

### PWA shell

A same-origin-only `public/sw.js` was added. It never intercepts Firebase/Gemini/Google cross-origin requests. Registration is production-only and deferred until the cloud profile is ready + browser idle time.

During Vite build, `vite.config.js` rewrites the service worker precache list with the actual hashed JS/CSS/static build output. Splash video is runtime-cached rather than precached to avoid downloading it twice during first install. Old MIND.EXE shell cache generations are removed on activation.

The final archive now includes `manifest.json` plus 16/32/180/192/512 PNG icons, and the Vite plugin copies them into `dist/`.

## Data invariants

Unchanged:
- `SCHEMA_VERSION = 2`
- `PROFILE_KEY = mind-exe-journal-state`
- `MEDIA_KEY = mind-exe-journal-media`
- `STRATEGY_SCHEMA_VERSION = 1`
- `STRATEGY_INDEX_KEY = mind-exe-strategy-index`
- `STRATEGY_TRADE_KEY = mind-exe-strategy-trade`
- `STRATEGY_MEDIA_KEY = mind-exe-strategy-media`
- Firestore path `users/{uid}/data/{safeKey}`
- Decision schema v1 and locked snapshot semantics

`core/journal-media.js`, `core/strategy-store.js` and `core/firestore-storage.js` are byte-identical to v5.2.1. `core/profile-store.js` changed only for full returned profile + parallel immutable writes described above.
